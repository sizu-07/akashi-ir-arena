# 明石光線

4人が1対1対1対1で遊ぶ赤外線対戦システムです。銃側はXIAO ESP32-S3 Plus、赤外線受信機3個、赤外線送信、テープLED、振動モーター、トリガー1個を使用し、Windows PCが試合を管理します。銃にブザーやリロードボタンはありません。運営はiPad、観客表示とカウントダウン音声・BGMはPCに接続したプロジェクターから操作します。現行ルールは90秒×4ゲーム・1発撃破・7秒自動復活・合計キル数勝負です。詳細は [ゲーム仕様 v0.8](docs/ゲーム仕様_v0.8.md) を参照してください。

射撃・被弾・撃破・復活・試合終了の効果音は、[音声ファイルの配置方法](assets/audio/README.md)に従い `assets/audio/effects/` に入れると投影画面から再生できます。

## 現在の状態

- PC管理プログラム、iPad運営画面、投影画面、ESP32ファームウェアを収録しています。
- 来場者向け整理券受付・待機表示、整理券運営、入場QR読取、ゲーム状態連携を収録しています。
- 回路設計と銃の3Dモデルは別担当です。`hardware/circuit/` の既存KiCadデータは旧構成で、現行ゲーム版との実機確認は未完了です。
- 電気・機械設計に必要な接続条件は `specs/` にあります。
- player1〜4の個人戦用BINは `firmware/release/players-4e/` に生成済みです。4台同時の試合、連続稼働、会場での確認は未実施です。旧v0.7以前のBINは個人戦に使用できません。

## 実行方法

1. Node.js 20以上をインストールします。
2. 動作確認は `起動_デモ.cmd`、実機4台での本番運営は `起動_本番.cmd` を開きます。
3. 初回だけ必要なパッケージと設定が準備され、ゲーム運営画面が自動的に開きます。
4. ゲーム運営画面は `http://localhost:8080/`、投影画面は `http://localhost:8080/display` です。
5. 整理券の運営・来場者受付・入場QR読取は、ゲーム運営画面上部から公開サーバーの各画面を開きます。

タブレットの運営画面は、PCと同じWi-Fiに接続し、PCのWi-Fi側IPv4アドレスを使って `http://<PCのWi-Fiアドレス>:8080/` を開きます。PCの `localhost` や基板用Ethernetの `192.168.137.1` はタブレットからの接続先ではありません。PCの投影画面にある「タブレット接続QR」もWi-Fi側アドレスを表示します。IPアドレスはネットワーク接続時に変わる場合があります。

`起動_デモ.cmd` と `起動_本番.cmd` を切り替えるときは、同じポートで動いているこのシステムの旧サーバーを自動終了してから、選んだモードで起動し直します。別のアプリが8080番ポートを使っている場合は、安全のため自動終了しません。

デモ版では「デモの確認対象」で「仮想端末4台（実機なし）」と「接続した実機」を切り替えます。実機を選ぶと仮想端末を停止し、「接続済み端末だけで動作確認」で1台から開始できます。投影画面の「表示を準備」と、参加端末の接続・時刻同期・構成確認が必要です。待機中、動作確認の途中経過表示中、または終了後に切り替えられ、切り替えると戦績・残り時間を戻します。確認対象は次回のデモ起動にも引き継ぎます。実機のWi-Fi設定・端末キーは本番と共通です。デモ版は公開整理券サーバーへゲーム連携通信を行いません。

本番版には動作確認・実機モーターデモの操作を表示しません。通常ゲーム用の4台、電池状態、投影準備、開始ACKを確認して通常試合を開始します。整理券連携が設定済みなら、先に「整理券メンバーを反映」を実行してください。本番APIからの動作確認要求も拒否します。

本番では第1〜3ゲームの終了後に途中経過を15秒表示し、4台と投影画面の準備が整えば次のカウントダウンへ自動で進みます。デモでは「このゲームを終了して途中経過へ」で時間を短縮し、次ゲームを手動開始できます。両モードの「試合全体を強制終了」は残りゲームを省略します。整理券は4名全員が入場確認されるまで通常試合へ進めません。処理の分担と運営手順は [ゲーム仕様 v0.8](docs/ゲーム仕様_v0.8.md) にまとめています。

`npm run validate` はソフトウェア・4台分のBIN・実機試験記録を別々に確認します。4台同時の実機試験は未実施なので、[実機試験記録](tests/実機試験記録.csv) の v0.8 項目が完了するまで総合判定は不合格になります。

整理券の正本は公開サーバーとSupabaseに一元化しています。ローカルに別の整理券サーバーを起動しないでください。詳細は [整理券システム 運用・配置手順](docs/整理券システム.md) を参照。

## フォルダ構成

| 場所 | 内容 |
|---|---|
| `apps/server/` | Windows PCで動く試合管理・通信サーバー |
| `apps/web/` | iPad運営画面とプロジェクター投影画面 |
| `apps/ticket-server/` | 外部整理券API、割当、認証、履歴、WebSocket |
| `apps/ticket-web/` | 来場者受付・整理券・運営・入場QR読取画面 |
| `assets/` | ルール説明動画などの共通素材 |
| `firmware/` | XIAO ESP32-S3 Plus用プログラムと書込み用BIN |
| `specs/` | GPIO、受信機3個、モーターなどのハードウェア要求 |
| `hardware/circuit/` | 回路担当者の提出先（既存KiCadデータは旧構成） |
| `hardware/gun-model/` | 銃モデル担当者の提出先 |
| `docs/` | 仕様、製作、操作、試験の説明書 |
| `tools/` | セットアップ、ビルド、書込み、検証用ツール |
| `tests/` | 自動テストと実機試験記録 |

`config/`、`data/`、`logs/`、`.local-archive/` は各PCだけで使い、GitHubには共有しません。Wi-Fiパスワード、運営PIN、銃ごとの鍵も共有しないでください。
