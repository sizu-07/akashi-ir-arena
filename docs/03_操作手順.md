# ③ 操作手順（v0.6）

[最初のページへ](../README.md)

PCだけで試す場合は最初の「PCデモ」から。実機運用は[製作手順](02_製作手順.md)と[完成確認チェック](04_完成確認チェック.md)を終えてから行います。展示予定：2026年10月31日・11月1日。

## 1. 最初はPCデモ

1. Project内の `起動_デモ.cmd` を開く。このPCはNode.jsと依存関係を取得済み。別PCならNode.js 20以上を用意し、Project内で `npm install` を先に実行。
2. PCブラウザーで `http://localhost:8080/`。`config/local.json` の `operatorPin` でログイン。PIN・鍵・Wi-Fiパスワードは外部へ送らない。
3. 別ウィンドウで `http://localhost:8080/display` を開き、「表示を準備」を押す。
4. 運営画面の説明動画・スコア表示、開始、デモ命中、停止を確認。HP100→75、4回で撃破を確認。「受信箇所」でrx1・rx2・rx3を個別に選択し、別試合で「3個同時」を選んでも100→75だけになることを確認。
5. デモ終了はサーバーのウィンドウでCtrl+C。デモと実機を同時に動かさない。

ルール初期値は2対2、HP100、ダメージ25、30発、リロード2秒、最大5発/秒、命中後無敵300 ms、味方撃ち無効、復活なし、5分。得点は撃破数、同点なら残HP合計、なお同点なら引き分け。開始前の運営画面で許可された数値のみ変更できます。


## 2. プロジェクターとiPad

メインPCでWindowsの表示を「拡張」に設定。PCブラウザーの `http://localhost:8080/display` を別ウィンドウにし、プロジェクター側へ移動して「表示を準備」。初回の音声/全画面許可はPCで1回操作が必要です。

iPadは同じSSIDで、Safariから `http://PCのIPv4:8080/`。iPadのlocalhostはPCを指しません。PINでログインし操作権を取得。投影のQRも使えますが、PCに複数NICがある場合は実際の有線IPの手入力を優先します。

「ルール説明」は7秒×5枚の繰り返し。「説明動画」は同じ要点の35秒H.264動画を再生します。**字幕のみ、音楽・ナレーションなし**。終わったら「スコア表示」へ戻します。開始・終了合図の電子音は投影プログラム側で鳴ります。iPadで会場前に再生操作を確認してください。


## 3. 当日の1試合

1. 電池セット・筐体・受信部・主電源を確認。前・左・右の3受信部を手で隠さない持ち方と、命中時に振動することを説明。
2. PC本番起動、投影準備、iPad運営ログイン。接続4/4、全台「v0.6対応」、通常モード、時計同期・電池警告なしを確認。
3. ルール説明→スコアへ戻す→名前/チーム/ルールを確認→開始。
4. 4台の準備ACKが揃ってから3秒カウントダウン。揃わなければ停止するため、警告を迂回しない。
5. 通信・電池の問題は一時停止で対処。電池交換は必ず主電源OFF、3本セットごと交換。再接続後に明示的に再開。
6. 試合終了→結果確認→必要ならCSV保存→次の試合を作成。

iPadが切れただけでは試合はPCで続きます。PCにも運営画面を用意し、操作権を引き継いで停止できます。銃の通信断は一時停止、PC再起動後の進行中試合は停止状態から復元します。最後の停止手段は各銃の主電源です。


## 4. 電池ローテーションと撤収

v0.5からの準備案は4丁×3セット×3本=**36本**を同じ型番で揃え、3本ずつセット番号を付けます。BQ-CC55は会場共用3台。標準AA3〜4本の充電は公称約3時間で、冷却時間や状態により延びます。[Panasonic公式](https://www.panasonic.com/global/energy/products/eneloop/en/lineup/charger-bq-cc55.html)

XIAO Plus・3受信機・モーターを含む新回路の実機で2時間ごとの交換が成立した場合の8時間運用例：0hセットA、2hセットB（Aを冷却・充電）、4hセットC、6h充電完了したA。ただし冷却・充電が6hに間に合うことを事前に試し、間に合わない場合は予備追加/休止時間を設けます。1時間しか持たない場合、この数量で連続運転できるとは限りません。

充電は銃の外、運営が管理する通風・不燃性の作業場所で説明書に従います。膨れ・損傷・異常発熱した電池は使わない。終了後は銃から電池を外し、端子が短絡しないケースで保管。

サーバー停止後に `data/live/` をバックアップ。PINや鍵のあるconfigは非公開。製造に渡すのは製造ZIPのみ。初日の不具合を記録し、変更した場合は翌日前に再試験します。

## 受信・振動の表示

参加端末カードに前・左・右の有効フレーム受信数、最後に命中した受信ID、振動出力の自己申告を表示します。受信数は再起動で0に戻ります。0は未受信という意味で、断線と区別できません。振動は180 ms、状態通知は1秒ごとなのでON表示を取り逃す場合があります。実際に回転したかは触感と電流で確認します。デモは通信と命中処理を再現し、実モーターは駆動しません。
