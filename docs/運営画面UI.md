# 運営画面の構成

ゲーム運営と整理券運営は、`apps/ticket-web/operator-shared.css` を共通で読み込む。
ゲーム側は `/operator-shared.css` を同じファイルへ対応付け、整理券側も同じURLで配信する。
公開用Dockerイメージには `apps/ticket-web` とともに含まれる。
来場者向けの受付・整理券ページも同じ共通スタイルを読み込み、`guest.css` でスマートフォン向けの配置を指定する。

## 判断基準

- 主色は指定の `#b94047`。白・薄い灰色・濃い文字を合わせる。
- 明石高専公式サイトの白地、えんじ色のアクセント、罫線と文字中心の情報整理を参照した。
- 目立つ色は主操作と現在地に使い、正常・注意・切断は文字と状態色を併記する。
- 現在の状態、次の操作、日常の作業、一覧、設定・履歴の順に配置する。
- 見出し、タブ、入力欄、操作結果の位置と見た目を両画面で揃える。
- 主要な操作ボタンは44px以上。キーボードフォーカスを見せ、狭い画面では縦に並べる。
- 主色と白の文字のコントラストは約5.4:1。小さい補足も薄くしすぎない。

## ゲーム運営

最上部に現在のゲーム番号、残り時間、個人別の累計キル数、接続確認、進行操作を配置する。
次にルール説明・投影切替と参加者の名前・キル・デス・射撃数・命中率を表示する。
詳細な電池・受信状況、Wi-Fi設定は下部または折りたたみとする。

通常の試合交代は「次の試合を準備」→「整理券メンバーを反映」→名前の確認→「試合を開始」。
本番は第1〜2ゲーム終了後に途中経過を15秒表示し、次ゲームを自動開始する。投影画面や端末の準備が整わない場合は途中経過で待機する。第3ゲーム終了後に合計キル数で優勝者を確定する。
デモは「このゲームを終了して途中経過へ」で各ゲームを短縮し、次ゲームを手動開始できる。「試合全体を強制終了」は途中経過中も使え、残りゲームを省略して結果を確定する。
試合中の新試合作成や、停止中の一時停止など、現在の状態で不要な操作は無効にする。
開始・再開・終了・補正のサーバー側判定と、メンバーの明示反映は維持する。

デモ版のみ「デモの確認対象」と「接続済み端末だけで動作確認」を表示する。確認対象は仮想端末4台または接続した実機で、待機中・終了後に切り替えられる。実機を選ぶと仮想端末を停止し、1台からの動作確認と実機モーター確認を使用できる。本番版は動作確認欄を除去し、通常試合の開始・再開を使用する。

## 整理券運営

最上部に体験中・呼出中・待機人数・次枠の空席と、呼出・入場QR・ゲーム運営への移動を配置する。
調整枠と全体案内をその直下に置き、受付開始・停止、待機列、グループ単位の対応へ続く。
個別操作用の整理券一覧は下部とし、履歴・詳細設定・掲示QRは折りたたむ。
全体案内の編集中／反映済みを示し、通常更新による入力の保護は維持する。
調整枠、15分単位の呼出、グループのスキップ・呼び戻しは既存の運用ルールに従う。
