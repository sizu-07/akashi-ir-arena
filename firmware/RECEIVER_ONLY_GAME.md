# player3用・ゲーム受信専用版

`receiver_only_game` は、通常ゲームの `src/main.cpp` を `GAME_RECEIVER_ONLY=1` でビルドする環境です。通常ゲームと同じ時刻同期、試合状態、開始ACK、`hit_candidate`、HP・復活通知を使用します。

## 接続と構成

- 端末：`gun-003`、銃ID 3、チームB。銃ID 1の送信元は登録情報によりチームAと判定します。
- ファームウェア：`0.7.1-rx44`。構成：`xiao-s3-plus-rx44-only`。
- 赤外線受信：GPIO44 / `rx1` の1個。USBで給電します。
- 送信、モーター、LED、ボタン、電池ADCは初期化・使用しません。電池電圧は未測定として表示します。
- PC：`192.168.137.1:1883`。今回の受信側は固定IP `192.168.137.4`、送信側の保存設定は `.2` です。
- Wi-Fi設定と端末キーはGit管理外の `config/provision/gun-003.json` とマイコン内に保存します。

## 本番の運営画面で確認

1. `起動_本番.cmd` を実行し、通常の運営画面にログインします。
2. 「端末の詳細・受信状況」でplayer3の接続、構成、前方の受信数を確認します。
3. 受信すると「直近の赤外線」に送信者、銃ID、チーム、敵味方、連番、射撃／救助を表示します。試合前でも確認できます。
4. 試合処理を確認する場合は、投影画面の「表示を準備」を押し、「接続済み端末だけで動作確認」を選んで開始します。受信専用構成は動作確認用の試合で使用します。

有効な赤外線を受信しただけではHPを減らしません。ACTIVE状態・開始確認・時刻同期が成立し、送信側の通常ゲームコードから同じ連番の `shot_fired` が届いたとき、PCが命中を確定します。固定ID・連番を送る送信診断コードだけでは発射報告が届かず、HPの確認はできません。送信側が未接続でも受信数と信号内の送信者IDは確認できます。赤外線内のIDは識別用で、暗号的な送信者認証ではありません。

2026年10月7日、COM4 / MAC `44:b1:76:ae:99:18` に書き込み、全書き込み領域のハッシュ一致を確認しました。本番サーバーでplayer3のみ接続済みとなり、ファームウェア `0.7.1-rx44`、チームB、時刻同期を報告することを確認しました。同日、実光で `0x40454447`（銃ID 1、連番21、射撃）を3回受信し、本番サーバーでも `rx1:3`、プレイヤー1・チームA → プレイヤー3・チームB、敵チーム判定を確認しました。待機中のためHPは100のままです。HP変化の実機確認には、送信側もゲーム用コードで接続して試合を開始する必要があります。

## ビルド・書き込み

```powershell
pwsh -File tools/build-firmware.ps1 -Environment receiver_only_game
pwsh -File tools/build-firmware.ps1 -Environment receiver_only_game -Upload -Port COM4
python tools/provision.py --port COM4 --file config/provision/gun-003.json
```

通常の4E基板には `legacy_4e_game`、このブレッドボードには `receiver_only_game` を使用します。
